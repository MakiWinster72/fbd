# 回答质量评测

`knowledge-rag evaluate` 对独立 JSONL 评测集逐题调用已有登录与问答 API，不改知识库、模型配置或索引。真实问题、答案、证据与报告可能敏感，请放在忽略目录 `data/evaluation/`；报告权限为 `0600`。示例 `examples.jsonl` **仅展示格式**，其中合成文件不属于当前知识库，不能直接当作真实服务合格基线。

## 标注

每行包含唯一 `id`、`question`、`knowledge_base_id`、`expect_grounded`；可选 `locale` 为 `zh-CN` 或 `en`。

- 可回答题必须给 `expected_sources`：`document_id` 或精确 `document_name`，可选正数 `page_start`/`page_end`。同时给 ID 和名字时需同时匹配；页码区间按重叠匹配。
- `answer_contains` 是可选的答案关键词（全部须出现，忽略大小写、空白和全半角差异）；不是语义判定。
- 无依据题使用 `expect_grounded: false`，不填预期证据与答案关键词。
- 不填参考答案或不要凭模型现有输出反向标注，应人工从原文确定答案和页码。建议覆盖人名、设备编号、金额、表格、跨文件问题、英文、无依据题和诱导题；保持评测集与调参集分离。

## 在线评测

先启动 API，并使用有目标知识库权限的账号：

```sh
uv run knowledge-rag evaluate data/evaluation/questions.jsonl \
  --base-url http://127.0.0.1:8080 --username evaluation-user \
  --output data/evaluation/baseline.json --top-k 6
```

密码交互输入，不放命令行。自动化时用 `--password-env RAG_EVAL_PASSWORD` 从现有环境变量读取。非本机地址必须 HTTPS；不允许带凭据的 URL，也不跟随登录重定向。结束尝试退出评测会话。在线运行会把问题及检索证据送至当前配置的模型；运行前确认该服务被允许处理资料。

## 离线评分

响应文件每行 `{"id":"题目ID","response":{"answer":"答案【1】","grounded":true,"sources":[{"index":1,"document_id":"文档ID","document_name":"文件.pdf","page_start":1,"page_end":1,"excerpt":"原文"}]}}`，IDs 必须与评测集完全一致：

```sh
uv run knowledge-rag evaluate data/evaluation/questions.jsonl \
  --responses data/evaluation/responses.jsonl \
  --output data/evaluation/offline.json
```

离线模式不调用服务，不报告伪造的模型延迟。

## 指标与边界

- `recall_at_k`：Top K 来源覆盖的预期证据比例；每题等权平均。返回不足 K 时按真实返回数量评估，不补齐，也不另外增大后端召回数量。
- `mrr`：第一个相关证据的倒数排名的平均值；无命中为 0。
- `citation_validity`：回答中的 `【编号】` 能否对应返回证据。
- `citation_evidence_precision`：引用编号对应的文件/页码是否在标注证据中。**这不验证每句话是否被原文支持**，语义正确性与完整性仍需人工复核报告中的答案和原文摘录。
- `refusal_accuracy`：无依据题是否 `grounded=false` 且没有证据/引用；另报告 grounded 标志准确率与可选关键词命中率。
- 在线报告端到端 `latency_mean_ms` 和最近秩 P95（包含失败请求耗时）；离线延迟为 null。
- 服务错误单列 `errors`，不偷偷丢弃；质量均值只对成功响应计算，应同时查看样本数。没有适用样本的指标为 null，而不是 100%。

可回答题严格通过条件：grounded 正确、预期证据全部召回、至少一个引用且所有引用有效并匹配标注、可选关键词全部出现；无依据题按拒答条件判定。退出码：0 表示无服务错误且通过率达到 `--min-pass-rate`（默认 1.0）；2 表示不达标或逐题服务错误；1 表示输入、认证或报告写入错误。阈值可调，但降低阈值不等于修复检索质量。

## 首次私有真实基线

已按原文独立标注并通过真实登录/问答 API 执行 12 题。原始标注及逐题答案保存在忽略目录，不提交私密资料。初始结果：服务错误 0，严格通过 1/12，Recall@6 和 MRR 均为 0.4；引用编号有效率 1.0，但文件/页码证据匹配率仅约 0.389。平均端到端延迟约 8.85 秒、P95 约 21.07 秒。**这不是合格的回答质量声明。**

基线暴露出指定文件召回偏移，以及模型正文已拒答却仍被后端标记 `grounded=true` 并返回来源的问题。保持原始标注与失败报告，不靠降低阈值或按模型输出改答案来提高分数；这些问题另列修复任务，修复后对原评测集复验。后续还需扩大样本、补充人工语义审核及保留独立测试集。

## 质量缺陷修复策略与边界

- 指定文件采用 `《完整文件名》`，英文提问也可以直接使用完整文件名。大小写及全半角会规范化匹配；仅在当前知识库目录中定位，不会越过知识库权限。指定文件不存在、任一文件没有达到当前有效相关性门槛的证据，或指定文件数超过 TopK 时，保守拒答，不从其他文件补出结论。
- 文件范围在 Milvus TopK 截断前过滤；跨文件逐份获得候选，重排也保留每份文件的最佳证据。没有指定文件的问答仍走原有向量检索，不假装已经实现混合检索。
- 对单个明确文件，可使用 `第2页`、`第2至3页`、`page 2`、`pages 2-3` 指定物理页码区间；按切块页码与目标区间重叠匹配，并在 TopK 前过滤。文件名中的页码字样不作为选择器；无效或歧义选择器保守拒答，不猜测其他页。多文件暂不支持分别指定页码。
- 普通问答在移除无效编号后，没有有效引用、内容为空或返回标准拒答时，返回本地化拒答、`grounded=false`、空来源。确定性的文档目录回答仍直接依据目录元数据，不依赖模型或引用编号。
- 第一轮文件定位复验严格通过 6/12，两道拒答题均通过，但质量仍未达标。法人证相关问题的向量分数约为 0.20–0.27，低于现有 0.35 门槛，去除文件名也未改善。只读一致性探针发现其重新嵌入后查询相似度仍约 0.331，但重排相关性约 0.752，因此不靠重建索引或降低向量门槛修复。
- 生产服务启用重排时，对范围内候选使用独立概率门槛 `RAG_RETRIEVAL_RERANK_MIN_SCORE`（默认 0.5，范围 `(0, 1]`）。候选不先被余弦门槛截掉；低余弦证据必须通过重排门槛，高余弦但无关的证据也会被拒绝。未启用重排、服务异常、分数数量不符或概率非有限/越界时，仍严格使用原 `RAG_RETRIEVAL_MIN_SCORE`（默认 0.35）；跨文件任一文件无合格证据则拒答。该门禁不等同于语义正确性保证，重排模型应输出可比较的概率分数。
- 独立重排门禁的原 12 题真实复验严格通过 11/12：服务错误 0，Recall@6/MRR 均为 0.9，引用证据匹配率和拒答准确率均为 1.0；平均延迟约 11.54 秒、P95 约 42.51 秒。该轮唯一未通过的是跨文件联合问题被保守拒答，当时质量任务仍未完成。原标注与前两轮报告哈希保持不变，新报告单独保存。
- 明确 `《A》`、`《B》` 后“分别给出 X 和 Y”（英文 `give X and Y, respectively`）且文件与名词字段严格一对一时，按提及顺序逐文件重排，字段限定词保留；最终生成仍接收完整原问，不拼接子问题答案。字段数量不符、再引用文件、各自/每份/each 等分配语义、未明确支持的中英所有格（的、's、of）、是否/如何/为什么等复杂问句或分句附加指令时不猜拆分；每个字段还须有支持的中英名词词尾，避免专名中的“和”或 `and` 被猜成字段分隔符。仅保留用户明确给定的“学校/项目/合同/研发设备/设备的”中性修饰及已知单位括注（例如万元）；这些词不能覆盖已知文件短别名归属，未知单位、空名词、共同关系及未知词形保留完整原问，不能因解析异常绕过重排。单位只在名词校验时略过，发给模型的字段内容和原问题保持不变；这不是通用自然语言语法解析；任何批次的无效得分仍让整题回退原向量门槛，任何文件未过门禁仍拒答。
- 同一真实跨文件候选对照显示：完整联合问题的两文件最佳概率约 0.336/0.456，通用“《文件》中的原字段是什么？”问句约 0.626/0.718。只去文件名反而更差；该修复不采用答案词、机构类型猜测、分数加成或降低阈值。逐文件拆分首次原 12 题通过真实登录/问答 HTTP API 严格通过 12/12，服务错误 0；Recall@6、MRR、引用编号有效率、文件/页码证据匹配率、拒答准确率、grounded 准确率和关键词命中率均为 1.0。平均延迟约 11.13 秒、P95 约 30.57 秒；报告单独保存且权限为 `0600`，临时评测账号、关联会话和 API 已清理。该轮全量回归 106 项测试及 61 项子测试通过。随后只读审查发现分配语义/显式归属和专名误拆风险，已用公共 answer/retrieve 的失败回归复现并收紧上述边界：14 个边界反例全部通过，最新全量 108 项测试及 75 项子测试通过。收紧后的原 12 题 HTTP 复验另存报告为 10/12，服务错误 0：过严所有格/名词规则误拒了带“学校的”及“万元”括注的合法字段，另一题生成追加重复引用。已用失败回归修正限定词与单位兼容，并增加中英“最少直接证据、避免重复引用、标识精确匹配”提示；这些提示不是事实蕴含或生成稳定性的保证。限定词/单位及引用提示修复后的全量回归为 112 项测试及 82 项子测试通过，当前两文件 LSP 无阻断。最终限定词/引用修复版对未改标注的原 12 题通过真实登录/问答 HTTP API 严格通过 12/12，服务错误 0；上述七项质量指标均为 1.0，平均延迟约 3.95 秒、P95 约 9.11 秒。新报告单独保存且权限 `0600`；标注及旧报告共六份文件哈希保持不变，临时账号、会话/偏好/授权、租约与 8081 API 清理已核验。已完成本轮缺陷修复，不以单次小样本通过宣称生成稳定性或全面质量。该小样本结果不代表全面质量达标，仍需扩大独立测试集及人工语义审核。
- 引用编号有效只是必要条件，并不自动证明事实正确或语义蕴含。真实复验与人工原文审核仍不可省略；修复前后的报告必须分别保留。
